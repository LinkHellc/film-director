# 关口

每个关口都用 AskUserQuestion 问本人，问题和选项照下面写（`<…>` 换成实际内容）。AskUserQuestion 会自动带一个"其他"让本人写自由文字，不用自己加。问之前把 `state.gates.<关口>` 改成 `"asked"`；问完就停下等回答。

本人回答后，统一做三件事：

1. 把回答原文追加进 `films/<片名>/requirements.md`：`- <时间> [<关口>] 选了"<选项>"；补充："<自由文字>"`。
2. 改 `state.gates.<关口>`：同意写 `"approved"`，要改或不同意写 `"rejected"`。
3. 按下面"选完之后"做。

本人在"其他"里写了自由文字：先照字面理解；拿不准是同意还是要改，就按"要改"处理，再问一次。

附带文件一律写成可以点开的完整路径（`E:/05_AI/04_Claude短片流/films/<片名>/...`），写在问题前面的说明文字里。

## G0：开工设置

**什么时候问**：`0-setup.md` 的环境检查做完以后。检查结果（缺什么、怎么装）写在问题前面的说明里。

**附带文件**：`films/<片名>/brief.md`

**问题和选项**（一次问 4 个问题）：

1. 问题：`片子多长？` 选项：`15 秒`、`30 秒`、`60 秒`
2. 问题：`画幅用哪种？` 选项：`16:9 横屏（现有工具都按这个做）`、`9:16 竖屏（草图、裁切、放大都要另写代码）`
3. 问题：`总预算多少？（只算视频生成，金额是估算，以账单为准）` 选项：`¥10`、`¥30`、`¥60`
4. 问题：`要配乐和字幕吗？` 选项：`都不要`、`只要字幕`、`要配乐（之后告诉我歌名、时长、BPM）`、`配乐和字幕都要（之后告诉我歌名、时长、BPM）`

**选完之后**：

- 写进 `state.settings`：`seconds`（数字）、`aspect`（`"16:9"` 或 `"9:16"`）、`budgetCNY`（数字）、`subtitles`（true/false）、`music`（不配乐为 null）。
- 选了配乐：再在对话里问歌名、时长、BPM，以及有没有参考片；回答写进 `requirements.md`，`settings.music` 写成 `"<歌名>，<时长> 秒，<BPM> BPM"`。
- 选了 9:16：告诉本人 `sketch.py`、`frames.py crop169`、`post.py concat` 都是按 16:9 写的，这几步要现写代码代替，再确认一次。
- 全部有了 → `gates.G0 = "approved"`，`stage = "story"`，打开 `stages/1-story.md`。

## G1：定故事

**什么时候问**：逐镜故事写好、`story` 审核"通过"以后。

**附带文件**：`films/<片名>/story/shots-v<n>.md`（审过的那一版）、`films/<片名>/reviews/story-v<n>.md`（审核回复）

**问题**：`逐镜故事审核通过了（一句话主题：<主题句>）。故事就这样定吗？`

**选项**：`故事定了`、`还要改（在其他里写改哪里）`

**选完之后**：

- `故事定了` → `gates.G1 = "approved"`，`stage = "board"`，打开 `stages/2-board.md`。从这时起才能画图。
- `还要改` 或自由文字 → `gates.G1 = "rejected"`，按本人说的改，存新版本 `story/shots-v<n+1>.md`，重新审 `story`，通过后再问 G1。

## G3：定画风

**什么时候问**：2–3 张样帧画好、你自己看过以后。

**附带文件**：`films/<片名>/style/look-v<n>.png`（每张都列出来，标上第几张），以及每张用的提示词文件。

**问题**：`这是 <张数> 张样帧，每张一种画风：<每张一句话描述>。用哪一张的画风？`

**选项**：`用第 1 张`、`用第 2 张`、`用第 3 张`（只有 2 张就去掉第三项）、`都不行，重画（在其他里写想要的方向）`

**选完之后**：

- 选了某一张 → 把那张的画风写成一句话，追加进 `requirements.md`（`[G3] 画风：……`，后面所有提示词的【画风】段都用这句），`gates.G3 = "approved"`，接着画设定图（`stages/3-style.md` 第二部分）。
- 都不行 → `gates.G3 = "rejected"`，按本人说的方向重写提示词，再画 2–3 张新版本，再问 G3。

## G4：报价（每批一次）

**什么时候问**：这一批每个镜头的 `pre-submit` 审核都"通过"、`quote.ts` 退出 0 以后。每份报价问一次，一份报价只对应一次提交。

**附带文件**：`films/<片名>/quotes/Q<n>.json`，以及这批每个镜头的 `shots/<镜头>/prompt-v<n>.txt`、`first-v<n>.png`、`last-v<n>.png`、`reviews/pre-submit-<镜头>-v<n>.md`。

**问题前面的说明**（照 `quote.ts` 的输出和 `quotes/Q<n>.json` 写）：

```
报价 Q<n>
镜头：S01（4.6 秒 → 计费 6 秒）、S02（……）
模型：<mini 或 2.5>（<模型 id>，¥<单价>/秒，720p）
合计：约 ¥<合计>　已花：¥<已花>　预算余额：¥<余额>
金额是估算，以账单为准。网关提交时按每镜上限预扣（mini 每镜 15 秒），出片后按实际结算退差额，账户余额要够预扣。
<是重拍或重试的话，写明是哪一镜、为什么、改了什么>
```

**问题**：`报价 Q<n>：<镜头数> 镜 <计费秒数> 秒，约 ¥<合计>。提交吗？`

**选项**（固定写法，`<n>` 和金额照报价填）：

- `批准 Q<n>（¥合计）`，例如 `批准 Q3（¥1.8）`
- `改用 2.5 重新报价`——只有当本次报价用的是 mini、并且 `config/pricing.json` 里 `models["2.5"].firstLastFrame` 是 `true`（2.5 支持首尾帧）时才出现。现在的配置里它是 `false`，所以这一项不出现，只问 `批准 Q<n>（¥合计）` 和 `先不拍` 两项。检查命令：
  `node -e "const p=JSON.parse(require('fs').readFileSync('config/pricing.json','utf8'));console.log(p.models['2.5'].firstLastFrame===true?'支持':'不支持')"`
- `先不拍`

**选完之后**：

- `批准 Q<n>（¥合计）`（或本人在自由文字里明确写了"批准 Q<n>"）→ 在这一轮里运行
  `node scripts/approve.ts <片名> Q<n> --said '<本人回答原文>'`
  （原文用单引号包住；原文里有单引号就写成 `'\''`）。退出 0 → `gates.G4 = "approved"` → 运行 `node scripts/seedance.ts submit <片名> --quote Q<n>`，按 `stages/5-prompts.md` 处理结果。退出 1 → 把原因告诉本人，不提交。
- `改用 2.5 重新报价` → 运行 `node scripts/quote.ts <片名> --shots <同样的镜头> --model 2.5`，用新报价号重新问 G4。旧报价留着，不批准它。
- `先不拍` → `gates.G4 = "rejected"`，不运行 `approve.ts`，问本人想先改什么，等本人说。
- 回答含糊（"可以""行""先这样"）→ 不算批准，原样再问一次 G4。
- AskUserQuestion 用不了、改在对话里用编号选项问时：请本人原样打出 `批准 Q<n>`（或选项原文 `批准 Q<n>（¥合计）`）。只回一个数字不算批准，原样再问一次 G4。
- `approve.ts` 只认两种回答：恰好是选项原文 `批准 Q<n>（¥合计）`（首尾空白不算）；或以 `批准 Q<n>` 开头、全文不含 不、别、勿、没、未、拒、取消、暂缓、撤、等、再说、？、?、吗。"好的，批准 Q3""批准 Q3？""先等等再批准 Q3"都不算，会退出 1；这时原样再问一次 G4，不改写本人的话。

**超预算时**（`quote.ts` 退出 2，输出以"超预算："开头）：不问 G4，改问：

- 问题：`这批要 ¥<合计>，加上已花 ¥<已花> 超过总预算 ¥<预算>。怎么办？`
- 选项：`少拍几镜（在其他里写拍哪几镜）`、`先不拍`
- 本人在自由文字里提高预算 → 改 `settings.budgetCNY`、记进 `requirements.md`，再运行 `quote.ts` 出新报价、问 G4。

## G5：看动态、听声音

**什么时候问**：每一批片段下载完、你逐镜抽帧看过、能剪的剪掉、能用代码修的修好以后。每批都问，**试拍的那 1–2 镜也要问**：试拍行不行得通由本人在这里定，本人选"都可以"之前，不给其余镜头报价、不提交（`stages/6-generate.md` 第 4、5 步）。

**附带文件**：每个镜头最新的 `films/<片名>/shots/<镜头>/clip-v<n>.mp4`（修过的话附修好的版本），以及你抽帧看到的问题清单。

**问题前面的说明**必须写明：

```
我没看过动态、没听过声音。我只看了抽出来的帧：<每镜一句看到了什么、发现了什么、怎么处理的>。
动作顺不顺、有没有抖、声音能不能用，要你看过、听过才算数。
```

**问题**：`请看一遍这批片段、听一下声音。这批可以用吗？`

**选项**：`都可以`、`有镜头要处理（在其他里写哪一镜、哪里不对）`、`声音不用，后期另配`

**选完之后**：

- `都可以` → 这批镜头的 `status` 改成 `"accepted"`。还有没拍的镜头（比如刚看完的是试拍那批）→ 这时才照 `stages/5-prompts.md` 第 4–6 步给下一批报价、问 G4。全部镜头都 accepted → `gates.G5 = "approved"`，`stage = "post"`，打开 `stages/7-post.md`。
- `有镜头要处理` → `gates.G5 = "rejected"`，按 `stages/6-generate.md` 的"有问题怎么办"处理那一镜（先剪、再代码修、最后才重拍，重拍要重新审核、重新报价、问 G4），处理完再问 G5。
- `声音不用，后期另配` → 记进 `requirements.md`；后期不用片段自带的声音，其余同"都可以"。

## 改图：首尾帧要改时（不编号）

**什么时候问**：`keyframes` 审核或你自己按 8 项检查，发现某个镜头的首帧或尾帧要改的时候（方法论："有问题就告诉我是哪张图、哪里不对，我同意了再改"）。`requirements.md` 里关口编号写 `[改图-<镜头>]`。

**附带文件**：要改的图、`reviews/keyframes-<镜头>-v<n>.md`、`frames.py compare` 的对比图。

**问题**：`<镜头> 的 <首帧/尾帧> 有这些问题：<逐条：哪张图、哪里不对、打算怎么改>。照这样改吗？`

**选项**：`照这样改`、`我来说怎么改（在其他里写）`

**选完之后**：按本人的意思改（只改一小块时把改好的那一块贴回原图），存新版本，重新自检、重新审 `keyframes`。

## 审核卡住：同一项连续 3 次不通过（不编号）

`requirements.md` 里关口编号写 `[审核卡住-<类型>-<镜头>]`。

**附带文件**：三次的 `reviews/<类型>[-<镜头>]-v<n>.md`。

**问题**：`<类型> <镜头> 的审核连续 3 次没通过，主要卡在：<逐条>。怎么改？`

**选项**：`按审核说的改`、`换个拍法（在其他里写）`、`这一镜先不做`

**选完之后**：照本人的意思改，再审；`这一镜先不做` → 这一镜 `status` 写 `"skipped"`，告诉本人片长会变短。
