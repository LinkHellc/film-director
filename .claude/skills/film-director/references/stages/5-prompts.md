# 阶段 5：写视频提示词，提交前审核，报价（`stage = "prompts"`）

方法论：出了问题要先怀疑提示词，再怀疑模型，无论如何都要把提示词写精细。固定用七段式，把每一秒发生什么都写下来。每条视频提交之前，都要另开一个 agent 把提示词和图片的每个细节核对一遍，它审核通过之后才能提交（规矩 3）。

## 每个镜头做什么

### 1. 写七段式提示词 `shots/<镜头>/prompt-v<n>.txt`

- 模板照 `../seven-part-prompt.md`，一段都不少。
- 【画风】用 G3 定下的那句画风；【人物】照抄设定图的固定特征（含位置）；【构图与配色】要和首帧对得上，颜色取自 `board/palette-v<n>.md`。
- 【镜头】里的"整段 X 秒"写这一镜的计费秒数（分镜表"生成秒数"一列，最少 4 秒）。
- 【逐秒】的时间轴覆盖整个生成秒数，不是只写到片中时长：尾帧对应的是**生成秒数**的最后一刻，不是片中时长的最后一刻；片中时长之后多出来的那段写成"静止，后期剪掉"。分镜表里"片中时间"和"生成秒数"两个数都要带上，对照着写（详见 `../seven-part-prompt.md`）。例外：分镜写明"生成 X 秒、后期剪出最好的 N 秒"的镜头，【逐秒】写满生成秒数里的完整动作，不写静止尾巴，后期在 `edl` 里写明剪哪一段。
- 写完对照 `../pitfalls.md` 逐行查一遍：谁先谁后写了吗？方向按画面左右写了吗？数量写死了吗？有没有"不要怎么样"的说法可以改成正面说法？
- 文件里只放提示词本身，不加标题和说明（`seedance.ts` 会把整个文件当提示词发出去）。

### 2. 提交前审核 `pre-submit`（必须通过）

`node scripts/review.ts prepare pre-submit <片名> --shot <镜头>`。资料是最新的提示词、首帧、尾帧、全部设定图、分镜表、配色。流程见 SKILL.md"审核怎么做"。

- 不通过：按回复改（改提示词就存 `prompt-v<n+1>.txt`；改图就回 `4-keyframes.md`，先按 `../gates.md`"改图"问本人），再审。
- 通过：这一镜 `status = "ready"`。
- 审核通过之后不要再改这一镜的提示词、首帧、尾帧；改了就要重新审（`seedance.ts submit` 会核对哈希，拦下来）。

## 报价和提交

### 3. 先拿一两个最难的镜头试拍

方法论的省钱做法：用 720p 生成（脚本固定 720p），后期再放大到 1080p；不用专门拍测试片，直接拍第一个正式镜头，能用就赚了；新的做法先拿一两个最难的镜头试一下，行得通再全部提交。

所以第一批只报 1–2 个最难的、已经 `ready` 的镜头；它们出片、你抽帧检查过，再按 `../gates.md` 的 G5 请本人看动态、听声音（`6-generate.md` 第 4 步）；本人在 G5 选了"都可以"后，才给其余镜头报价。你自己的抽帧检查不能代替本人的 G5。模型默认用 mini（`state.settings.model`）；本人要用 Seedance 2.0（满血版，¥0.45/秒，单镜 4–15 秒，支持首尾帧）时报价加 `--model 2.0`；2.5 现在不支持首尾帧，不能用。

### 4. 报价

`node scripts/quote.ts <片名> --shots S01,S02`（用 mini）
`node scripts/quote.ts <片名> --shots S01,S02 --model 2.0`（用 2.0：本人说过要用 2.0，或在 G4 选了"改用 2.0 重新报价"）

- 退出 0：打印"报价 Q<n>：……"，报价写在 `quotes/Q<n>.json`。按 `../gates.md` 的 G4 问本人（说明里写镜头、秒数、模型、合计、已花、余额、"金额是估算，以账单为准"）。
- 退出 2、输出以"超预算："开头：按 `../gates.md` G4 的"超预算时"问本人。
- 退出 2、其他原因（"还没有通过提交前审核""还没有设总预算"……）：照原因补上再报价。

### 5. 本人选了"批准"才运行 `approve.ts`

只在本人这一轮的回答明确是 `批准 Q<n>（¥合计）`（或亲口写了"批准 Q<n>"）时：

`node scripts/approve.ts <片名> Q<n> --said '<本人回答原文>'`

- 退出 0：`gates.G4 = "approved"`，接着第 6 步。
- 退出 1：把输出告诉本人，不提交。
- 本人选了"先不拍"或回答含糊：不运行，按 `../gates.md` G4 处理。

### 6. 提交

`node scripts/seedance.ts submit <片名> --quote Q<n>`

| 退出码 | 怎么做 |
|---|---|
| 0 | 全部提交了。`stage = "generate"`，按 SKILL.md"等出片"在后台运行 `node scripts/seedance.ts wait <片名>`，打开 `6-generate.md`。 |
| 1 | 看输出。闸门原因（审核后改过文件、没有批准、超预算、已提交过……）→ 照原因改，需要时重新审核、重新报价、重新问 G4。"另一个提交正在进行" → 不删锁，把输出原样告诉本人。"提交结果不明" → 可能已扣费，不要重发，把输出原样告诉本人请他到网关任务日志核对。"网关拒绝了……没有建任务" → 读原因改参数，重新报价。输出"已提交 k 镜"且 k > 0 时，那几镜已在生成，照样在后台 `wait`。 |
| 4 | 欠费：其余镜头没提交。按 `6-generate.md`"欠费"处理：粗剪已有片段，告诉本人，停下。 |
| 7 | 已在网关建了任务但没记上账，锁保留。立刻停下，把命令打印的全部内容原样告诉本人；不补记、不删锁、不重新提交。 |

## 产物

- `shots/<镜头>/prompt-v<n>.txt`：七段式视频提示词（`pre-submit` 审核的资料，提交时发的就是编号最大的这一版）
- `reviews/pre-submit-<镜头>-v<n>.*`：提交前审核
- `quotes/Q<n>.json`（`quote.ts` 写）、`approvals/Q<n>.json`（`approve.ts` 写）、`spend.jsonl`（`seedance.ts` 写）——都不要手改

## 完成后 `state` 怎么改

- 每镜 `pre-submit` 通过：`shots.<镜头>.status = "ready"`。
- 第一批 `submit` 退出 0：`stage = "generate"`（提交成功的镜头 `status` 由脚本改成 `"generating"`）。之后的批次在 `6-generate.md` 里照本文件第 4–6 步做。
